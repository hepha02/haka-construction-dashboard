# HAKA Construction Admin

## 2026-10-30 운영 오류 점검과 수정본

- 운영 사이트의 수정 저장 실패는 DB의 기존 UPDATE 규칙이 신청 상태를 유지한 변경을 거부하는 것으로 확인했습니다. 이 규칙을 로컬 Postgres에서 재현했습니다. 아래의 승인 전 수정·취소 migration은 계속 운영 미적용이며, 프런트엔드만 배포해서 이 문제가 해결된다고 안내하면 안 됩니다.
- 새 첨부는 `사용자ID/분류/UUID.확장자` 형식의 ASCII 경로에 저장하고 원래 한글·유니코드 파일명은 첨부 메타데이터와 화면 표시용으로 유지합니다. 결제 증빙·업체 서류·공사 시작 자료에 같은 로직을 적용합니다. 기존 객체나 URL을 변경하거나 덮어쓰지 않습니다.
- 수정 저장 시 DB 권한 오류·동시 변경·예외가 발생해도 입력과 기존 첨부를 유지하고 버튼을 다시 활성화합니다. 응답을 확인하지 못한 저장은 재제출 전에 내역을 확인하도록 안내합니다.
- 실제 SDK의 요청을 로컬 가짜 HTTP 응답으로 검증합니다. 한글, 분해형 한글, 공백·괄호, 이모지, 외국어, 확장자 없는 파일명을 확인하며, 실제 운영 Storage에 테스트 파일을 올리지 않습니다.
- 기존 반려·재등록 기록과 입력자를 알 수 없는 과거 신청은 자동으로 변경하거나 입력자를 추정하지 않습니다. 운영 적용은 권한·과거 신청 처리 범위와 최신 백업을 확인한 별도 릴리스로 진행해야 합니다.

## 승인 전 수정·취소 개편

결제 신청(내 신청 작성·정정) → 결제 검토·승인(관리자) → 은행 이체 파일 생성 → 공사비 집계 순서로 배치했습니다. 승인 전에는 입력자 본인만 수정·취소할 수 있고, 승인 후에는 금액·증빙을 잠급니다. 취소·반려 건은 삭제하지 않고 원본을 보존한 채 새 신청으로 이어집니다.

`supabase/migrations/20261029092713_payment_request_lifecycle.sql`은 **운영 미적용 검토본**입니다. 작성자, 버전, 취소·반려 사유와 변경 이력을 추가하고 DB에서도 상태·권한을 검사합니다. 과거 기록의 작성자는 추정하지 않습니다. 과거 기록은 전체 내역에서 계속 조회하며, 수정·취소 권한을 임의로 부여하지 않습니다.

`npm test`는 PGlite의 로컬 Postgres에 가상 사용자·데이터만 생성해 실제 migration SQL과 RLS·트리거를 실행합니다. 운영 Supabase에는 접속하지 않습니다. 로컬 테스트 통과는 실제 Supabase/PostgREST 연동 검증이나 전체 DB 복원 검증을 대체하지 않습니다.

운영 반영 전에는 최신 백업과 별도 환경 복원 검증, 적용 시점의 정책·스키마 재확인, 사용자 작업 시간 조율이 필요합니다. 검토된 migration과 프런트엔드를 순서대로 반영하고 기존에 열어 둔 화면을 새로고침해야 합니다. 개발 단계에서는 이를 실행하지 않습니다.

공사비 관리용 관리자 대시보드입니다.

## 운영 데이터 보존

- 운영 프로젝트는 실무자가 계속 사용하는 상태입니다. 개발 중 운영 DB에는 읽기 전용으로 접근합니다.
- 기존 데이터에 `supabase/schema.sql`을 다시 실행하거나 초기화/시드/복원 명령을 적용하지 마세요.
- 백업 파일은 `.private-backups/`에 보관하며 Git 및 웹 배포에 포함하지 않습니다.
- DB의 물리 백업과 별도로 업무 데이터 JSON과 Storage 원본을 복사합니다. JSON 내보내기는 DB 전체 복원본을 대체하지 않습니다.
- `node scripts/verify-backup.mjs <백업폴더>`는 파일 수·크기·SHA-256을 검증합니다. 전체 DB 복원 검증과는 다릅니다.
- 변경은 검토용 브랜치에서 준비하고, 운영 반영 직전에 최신 백업 및 신규 입력 내역을 재확인합니다.

## 집계 기준

승인 공사비는 승인된 신청 금액의 합계입니다. 송금완료 원가, 원천징수, 실지급액과 미송금 승인액을 구분합니다. 기존 장부 품목 원가는 별도 집계 기준으로 조회하며 결제 금액과 합산하지 않습니다. 기간은 신청일 기준입니다.

사업소득 3.3% 건은 아마란스 신고 확인 알림만 제공합니다. 신고서 작성이나 신고완료 추적은 수행하지 않습니다.

## 개발 환경 연결

필요한 경우 별도 개발 프로젝트의 연결 값을 로컬 `.env`에 넣습니다. 서비스 역할 키는 브라우저 코드에 넣지 않습니다.

```env
VITE_SUPABASE_URL=your-project-url
VITE_SUPABASE_ANON_KEY=your-anon-key
```
